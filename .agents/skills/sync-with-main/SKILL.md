# sync-with-main

A branch open for a while collides with `main`, GitHub shows **"This branch has conflicts that must be resolved"**, and the merge button disappears. [`docs/git-workflow.md`](../../../docs/git-workflow.md) is the source of truth; this skill covers the careful execution and routine conflicts.

## Establish a recovery point

```bash
git branch --show-current
git rev-parse HEAD
git rev-parse --abbrev-ref --symbolic-full-name '@{u}'
git status --short
git log --oneline origin/main..HEAD
```

Record the branch, HEAD, upstream, working-tree changes, and unpushed commits before changing history. The working tree must be clean. Commit the intended work first; in a worktree, avoid `git stash` because every worktree shares the same stash stack.

Branches based on Lymi's pre-2026-09-06 history are a separate case. Create a fresh branch from `origin/main` and transplant only the unique commits or net diff, following the migration section in `docs/git-workflow.md`. Keep the original branch until the replacement is verified.

## Rebase onto main

```bash
git fetch origin
git rebase origin/main
```

Rebase keeps Lymi's release history linear. During a rebase, `ours` is the updated `origin/main` side and `theirs` is the branch commit currently being replayed.

## The conflicts that resolve themselves

**`pnpm-lock.yaml`** — generated, never hand-written. Resolve any package manifest conflicts first, take main's lockfile, then regenerate:

```bash
git checkout --ours pnpm-lock.yaml
pnpm install
git add pnpm-lock.yaml
```

A hand-edited lockfile installs something different from what it claims and fails somewhere unrelated later.

**`apps/web/src/client/routeTree.gen.ts`** — generated by the TanStack Router plugin. Take either side, then let the dev server or a build rewrite it:

```bash
git checkout --ours apps/web/src/client/routeTree.gen.ts
pnpm --filter @lymi/web build
git add apps/web/src/client/routeTree.gen.ts
```

**`apps/*/src/locales/*.po`** — Lingui catalogs. Never edit conflict markers in a `.po` file; a hand merge duplicates headers and drops translations. Take `main`'s catalogs, regenerate them from the rebased code, then fill the branch's empty `uk` and `ru` entries with the [translate skill](../translate/SKILL.md):

```bash
git checkout --ours -- 'apps/*/src/locales/*.po'
pnpm i18n:extract
git add 'apps/*/src/locales/*.po'
```

Run extraction after the conflicting source files are resolved, so the catalogs match the code being replayed.

**`apps/web/migrations/meta/_journal.json`** — two branches each added a migration. Keep both entries, in timestamp order, and check that the two migration files have distinct numeric prefixes. If they collide, renumber yours to follow main's and update the journal entry to match. Then run `pnpm db:migrate` against the local D1 and confirm it applies cleanly.

## What stops for a person

A conflict in app code means two changes touched the same lines. Resolve it only when you can see which side is right and say why. Otherwise stop and hand it back — guessing here is worse than asking.

`git rebase --abort` returns the branch to the recorded HEAD. Use it when the correct resolution is unclear and hand the decision back with the conflicting paths and both intentions summarized.

## Finish

```bash
git rebase --continue         # repeat conflict resolution and continue as needed
pnpm verify:changed
git push --force-with-lease
gh pr view --json mergeable,mergeStateStatus
```

Run the checks after the rebase completes. Confirm that the final diff still contains only the intended change before pushing. `--force-with-lease` protects remote work that appeared after the fetch; a lease failure stops for inspection instead of escalating to an unconditional force-push. `MERGEABLE` means the conflict is cleared.

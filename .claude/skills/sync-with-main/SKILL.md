# sync-with-main

A branch open for a while collides with `main`, GitHub shows **"This branch has conflicts that must be resolved"**, and the merge button disappears. Most of it is mechanical.

## Merge, don't rebase

```bash
git status --short                 # must be clean; commit first if not
git fetch origin main
git merge origin/main
```

Merge rather than rebase. The repo squash-merges, so the merge commit vanishes on merge anyway, and a rebase would force-push a branch that may already be open for review.

If the working tree is dirty, commit first. In a worktree, never reach for `git stash` — the stash stack is shared with every other worktree and another session may pop your entry.

## The conflicts that resolve themselves

**`pnpm-lock.yaml`** — generated, never hand-written. Take main's copy and regenerate:

```bash
git checkout --theirs pnpm-lock.yaml && pnpm install && git add pnpm-lock.yaml
```

A hand-edited lockfile installs something different from what it claims and fails somewhere unrelated later.

**`apps/web/src/client/routeTree.gen.ts`** — generated by the TanStack Router plugin. Take either side, then let the dev server or a build rewrite it:

```bash
git checkout --theirs apps/web/src/client/routeTree.gen.ts
pnpm --filter @lymi/web build && git add apps/web/src/client/routeTree.gen.ts
```

**`apps/web/migrations/meta/_journal.json`** — two branches each added a migration. Keep both entries, in timestamp order, and check that the two migration files have distinct numeric prefixes. If they collide, renumber yours to follow main's and update the journal entry to match. Then run `pnpm db:migrate` against the local D1 and confirm it applies cleanly.

## What stops for a person

A conflict in app code means two changes touched the same lines. Resolve it only when you can see which side is right and say why. Otherwise stop and hand it back — guessing here is worse than asking.

`git merge --abort` puts the branch back exactly as it was and loses nothing. Reach for that, never `git reset --hard`.

## Finish

```bash
pnpm check && pnpm typecheck && pnpm test
git commit --no-edit          # if the merge is still open
git push
gh pr view --json mergeable,mergeStateStatus
```

`MERGEABLE` means the conflict is cleared. Run the checks *after* the merge, not before — a green branch plus a green `main` can still fail together, and that failure is a real problem to fix rather than a reason to re-sync.

# Product analytics

Understand how a visitor becomes a learner and completes a useful review. EU PostHog project 292417 serves both production domains. [How Lymi is doing](https://eu.posthog.com/project/292417/dashboard/1015528) is the weekly check, emailed on Mondays, and the [growth dashboard](https://eu.posthog.com/project/292417/dashboard/1013943) shares its retention charts; both use `review_graded` for learners and retention, so preserve its mode, grade and accepted-server-write meaning. The project's internal-users cohort matches the `is_internal` person property.

## Identity and opt-out

Analytics store nothing on the device, so there is no consent banner on either origin. The public site initializes PostHog with `cookieless_mode: "always"` and memory persistence: every event carries the `$posthog_cookieless` sentinel, and PostHog's stateless cookieless mode (project setting) replaces it with a hash of the day, address, host and browser, then drops the address and user agent. Public visitors are never identified, so a public visit is never joined to an account or to another day.

The product measures every signed-in account under Lymi's legitimate interest in understanding and improving the product, unless `user_settings.analytics_consent` is `false`. Null and true both mean on; an opt-out never lapses. There is no switch: a learner objects by emailing hello@lymi.app, as the privacy policy says, and an operator records it by setting that column to `false` for the account. The learner-only `/api/settings/analytics-consent` still writes the same column, refuses any origin but the product's own, and lets newer timestamps win atomically. Browser producers wait until the account and its setting are read, then `identify` the opaque account ID with memory persistence; turning analytics off resets the SDK and suppresses capture. A signed-out product page is counted under an in-memory anonymous ID that `identify` joins to the new account when sign-up completes in the same page. HTTP, API, MCP and Workflow producers read the same account setting, once per HTTP request or durable run; the phone app's requests count like any other signed-in request.

The phone follows the product's rules. Its release builds against production wait for the signed-in learner's settings, then `identify` the same opaque account ID unless `analytics_consent` is `false`; an opt-out, sign-out or account switch resets the SDK and drops every unsent usage event. Each launch starts under a new anonymous ID, because the SDK's stored distinct ID, anonymous ID and session are never written to its file storage, and `identify` joins it to the account. Signed out, the phone sends no usage event. Usage events wait in a queue of their own, separate from error reports, that sends only while the signed-in account is identified and allows analytics, and only that account's events (`apps/mobile/src/telemetry/usage-queue.ts`). The SDK's file storage keeps both queues, already scrubbed and each event with the opaque account ID it was captured under, so a crash report is sent on the next launch and usage from a launch offline is sent once that account's settings are read again; a retried batch keeps each event's UUID, which PostHog deduplicates. Every phone event has `surface=phone`, `$os`, `$app_version` and `$app_build`, and no SDK device, screen or locale property. A server outcome from a request carrying `x-lymi-client`, such as a grade or added cards, keeps `surface=worker` and adds `client=phone` with the same `$os`, `$app_version` and `$app_build`, and `app_update` once the phone names its over-the-air update, so phone use is the phone's events plus the server's outcomes with `client=phone`.

Both origins send through `POST /ingest/*`, which only forwards PostHog's capture endpoints. The Worker sets `$geoip_country_code` and `$geoip_country_name` from Cloudflare's country and `$geoip_disable`, so PostHog's own lookup never runs, and forwards the visitor's address only for cookieless events, whose hash needs it. Profiles contain only `ui_locale` and a positive `is_internal` flag for explicitly configured internal IDs. The confirmed personal and work accounts and the explicitly named Spark onboarding test account are listed in `INTERNAL_ACCOUNT_IDS`; use a local account lookup to extend it, never send the lookup's names or addresses to PostHog. An absent internal flag never overwrites a manually classified profile.

A visit's first touch is the first public page, an external referrer hostname and bounded `utm_source`, `utm_medium` and `utm_campaign` labels. With no storage to keep it, public pages add it to followed links as `lp`, `ref` and the campaign keys, and only when there is a referrer or campaign to carry. The product reads it from its arrival address and sends it with sign-up: the email form in the `x-lymi-first-touch` header, Google in OAuth `additionalData`. The server validates it before `signed_up` records it. Error monitoring works independently and strips private messages, URLs and context before delivery. A product browser error carries `route`, the same route pattern as `$pageview`, and `release`, the commit its bundle was built from, which matches the Worker's version tag. A chunk an older build named, after a deploy replaced it, reloads the page once per build instead of being reported; only a failure that survives that reload reaches PostHog. The phone's release builds report uncaught errors and unhandled rejections the same way, without a person profile; a report from an account in `INTERNAL_ACCOUNT_IDS` also carries the event property `is_internal=true`. Session replay, click autocapture, surveys, feature flags and performance autocapture remain off.

## Contract and producers

`packages/core/src/analytics.ts` owns the typed event catalog, permitted producers and Zod property allowlists. `packages/client/src/analytics.ts` is the browser adapter for the web and the site, the only module in `@lymi/client` that loads `posthog-js`; Biome's `noRestrictedImports` keeps it out of the rest of the package and out of `apps/mobile`, so shared client code stays portable to the phone. `apps/mobile/src/telemetry` is the phone's producer (`phone` in `analyticsProducers`). `apps/web/src/server/posthog.ts` adapts accepted service outcomes. Call `captureAnalytics` for a browser interaction and `track(ctx.analytics, event)` for a committed server outcome; never call PostHog directly from a screen or service. Every delivered event has `ui_locale` (`en`, `uk`, `ru`), `surface`, and `schema_version=1`. Background locale uses the account preference, then English; browser events use the active document language.

Page properties contain approved routes, with private dynamic IDs replaced by `:item`; a public page keeps its published deck's or changelog update's slug, which is public. Queries and fragments are omitted. The first page view of a page load adds the visit's referrer hostname and campaign labels. Search terms, `utm_term`, `utm_content`, auth tokens, names, emails, private card/deck IDs, card content, MCP arguments, responses and prompts are excluded. The adapter also removes SDK-generated top-level person properties, including initial URLs; approved profile fields remain inside the sanitized event properties.

| Event | Owner and firing condition |
| --- | --- |
| `$pageview` | Browser initial load and committed product navigation, deduplicated on initialization while actual navigations retain their counts; the phone sends one when its signed-in screen changes, under the web page that screen stands for (`/you/insights` is `/insights`, a deck is `/library/:item`) or its own `/you`, `/capture`, `/streak`, `/feedback`, `/share` and `/series-order`; `$pathname`, `$current_url` and `$host` contain only safe production paths; the first of a page load adds `referrer` (also `$referring_domain`) and campaign labels, or `$referring_domain=$direct` when it has no referrer, so PostHog's channel type counts it as Direct rather than Unknown. |

| `onboarding_finished` | Compatible server outcome after welcome is saved, with a fixed learning kind, `joined` for an account arriving with a deck, or `skipped`; no typed language answer is collected. |
| `signed_in` | Auth session creation; do not interpret as every explicit sign-in click or as a session refresh. |

| `review_undone` | Server, when an accepted grade is first taken back: the undone grade's `mode` and `grade`; undoing it again adds no event. Answers how often learners take back a grade, which only the phone's swipe does today; subtract it from `review_graded` for net grades. |
| `streak_ended`, `rest_day_used` | Server, after the response, when a learner-local day's row is first created by its first grade or a nothing-due visit; the request that creates it judges the days since the last active one. `rest_day_used` per rest day among them and `streak_ended` when the run did not survive, both with `streak_days`, the run the last active day left. | `hook_added` | Committed edit that gives a card without a hook its first one, with the hook's field `source` (`ai` when it is the AI's draft as kept). Replacing a hook adds no event. |
| `cards_archived` | Committed card archive, one event per `origin` (`typed`, `api`, `ai_mcp`, `import`, `other`) with `count` and `ai_written`, the archived cards with any AI-written field. Archiving an archived card, deck and import archives add nothing. |
| `reminder_sent` | Scheduled reminder delivered to the push service, with the learner's `backlog`, once per device sent to, so a learner with two devices counts twice; failed and expired sends add nothing. |
| `$ai_generation` | Each OpenAI text call for enrichment, hook drafts, import language detection and choosing a shared term's deck: model, input, output, reasoning and cached tokens, latency, error and HTTP status, in PostHog's LLM analytics shape. The server prices calls to models in `textCallCost`'s table (`packages/core/src/analytics.ts`) and sends `$ai_input_cost_usd`, `$ai_output_cost_usd` and `$ai_total_cost_usd`; a model missing from it is left for PostHog to price, so add a model there when `OPENAI_TEXT_MODEL` changes. No prompt or reply is sent (`$ai_input` and `$ai_output_choices` are not in the contract); `$ai_span_name` names the feature. |
| `cards_added` | Committed additions, excluding duplicate cards and edits: `source`, `count`. `typed`, `api`, `ai_mcp`, `anki`, `mochi`, `noji`, `lymi` are implemented; CSV/Quizlet remain reserved until adapters exist. `ai_mcp` denotes the channel, not authorship. |

| `welcome_step_viewed`, `welcome_step_finished` | Browser observes current guide step and progression for `deck`/`cards`; first accepted non-import grade finishes `review` on the server. The welcome flow uses `hello`, `kind`, `language`, `goal`, `start`; an account arriving with a deck uses only `hello` and `goal`; progression and saved completion fire step outcomes, and a saved Skip fires its current step with `skipped=true`. Each Welcome step is viewed and finished at most once per page load until Welcome ends, so Back and Next again repeat nothing, and a Skip on a step already finished adds nothing. The server emits `setup` once for overall completion or Skip, with `skipped=true` only when both learning kind and daily goal are absent. Existing progress on mount is not replayed as completion, so a deck or cards added away from the guide finish no step; measure that progress with `cards_added`. |

A measured review leg begins when a card is presented. Finished legs end at a goal or confirmed empty queue and count net recall attempts since presentation, including repeated cards and subtracting Undo. Abandonment reports net `cards_done` against the frozen initial planned `card_count`; left, navigation and pagehide are observable exits. Continue starts another leg and does not retain first-session eligibility after actual work. An empty screen, failed refresh or offline exhaustion cannot manufacture a completion. Browser shutdown delivery is best effort; absence of abandonment proves nothing. These counts are attempts, not unique cards, and are distinct from accepted server grades queued offline.

The first-review marker is stored separately from mutable/imported history, so retries and Undo do not repeat activation. It is written after the grade's response, only while PostHog is configured. Historical non-import reviews seed existing learners as already active. Marker errors never roll back grades. Account deletion cascades markers and settings with the account.

## Extend and verify

For each feature, state the measurement question in the PR's Instrumentation section, reuse or add a catalog event, document its owner and exact firing condition here, and test allowed properties plus meaningful retry/failure behavior. Use fixed categories and counts rather than user-entered strings. Keep outcome ownership on the server and interaction ownership in the browser. If no event answers a useful question, state why. Add properties compatibly; a changed meaning needs a new event or explicit schema migration.

Run contract/identity tests, service tests and the repository gates. Development and previews never send to PostHog. Before using a production funnel, verify one journey in live ingestion: cookieless public page with country → sign-up with its first touch → identify → committed membership/cards → accepted review, matching distinct IDs and locale; also verify that an account with `analytics_consent` set to `false` stops delivery. Do not infer live delivery from a passing test or a green deploy. Filter person `is_internal=true` out of growth charts. Project timezone is Europe/Tallinn. A phone event is verified the same way, from a TestFlight build: launch, screen, review leg and a grade with `client=phone`, under the learner's distinct ID.

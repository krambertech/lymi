# Product analytics

Understand how a visitor becomes a learner and completes a useful review. EU PostHog project 292417 serves both production domains. The [growth dashboard](https://eu.posthog.com/project/292417/dashboard/1013943) uses `review_graded` for weekly learners and retention; preserve its mode, grade and accepted-server-write meaning.

## Identity and opt-out

Analytics store nothing on the device, so there is no consent banner on either origin. The public site initializes PostHog with `cookieless_mode: "always"` and memory persistence: every event carries the `$posthog_cookieless` sentinel, and PostHog's stateless cookieless mode (project setting) replaces it with a hash of the day, address, host and browser, then drops the address and user agent. Public visitors are never identified, so a public visit is never joined to an account or to another day.

The product measures every signed-in account under Lymi's legitimate interest in understanding and improving the product, unless `user_settings.analytics_consent` is `false`. Null and true both mean on; an opt-out never lapses. There is no switch: a learner objects by emailing hello@lymi.app, as the privacy policy says, and an operator records it by setting that column to `false` for the account. The learner-only `/api/settings/analytics-consent` still writes the same column, refuses any origin but the product's own, and lets newer timestamps win atomically. Browser producers wait until the account and its setting are read, then `identify` the opaque account ID with memory persistence; turning analytics off resets the SDK and suppresses capture. A signed-out product page is counted under an in-memory anonymous ID that `identify` joins to the new account when sign-up completes in the same page. HTTP, API, MCP and Workflow producers read the same account setting, once per HTTP request or durable run; the phone app's requests count like any other signed-in request.

Both origins send through `POST /ingest/*`, which only forwards PostHog's capture endpoints. The Worker sets `$geoip_country_code` and `$geoip_country_name` from Cloudflare's country and `$geoip_disable`, so PostHog's own lookup never runs, and forwards the visitor's address only for cookieless events, whose hash needs it. Profiles contain only `ui_locale` and a positive `is_internal` flag for explicitly configured internal IDs. The confirmed personal and work accounts and the explicitly named Spark onboarding test account are listed in `INTERNAL_ACCOUNT_IDS`; use a local account lookup to extend it, never send the lookup's names or addresses to PostHog. An absent internal flag never overwrites a manually classified profile.

A visit's first touch is the first public page, an external referrer hostname and bounded `utm_source`, `utm_medium` and `utm_campaign` labels. With no storage to keep it, public pages add it to followed links as `lp`, `ref` and the campaign keys, and only when there is a referrer or campaign to carry. The product reads it from its arrival address and sends it with sign-up: the email form in the `x-lymi-first-touch` header, Google in OAuth `additionalData`. The server validates it before `signed_up` records it. Error monitoring works independently and strips private messages, URLs and context before delivery. Session replay, click autocapture, surveys, feature flags and performance autocapture remain off.

## Contract and producers

`packages/core/src/analytics.ts` owns the typed event catalog, permitted producers and Zod property allowlists. `packages/client/src/analytics.ts` is a browser-only export, separate from the mobile client's root. `apps/web/src/server/posthog.ts` adapts accepted service outcomes. Call `captureAnalytics` for a browser interaction and `track(ctx.analytics, event)` for a committed server outcome; never call PostHog directly from a screen or service. Every delivered event has `ui_locale` (`en`, `uk`, `ru`), `surface`, and `schema_version=1`. Background locale uses the account preference, then English; browser events use the active document language.

Page properties contain approved routes, with private dynamic IDs replaced by `:item`. Queries and fragments are omitted. The first page view of a page load adds the visit's referrer hostname and campaign labels. Search terms, `utm_term`, `utm_content`, auth tokens, names, emails, private card/deck IDs, card content, MCP arguments, responses and prompts are excluded. The adapter also removes SDK-generated top-level person properties, including initial URLs; approved profile fields remain inside the sanitized event properties.

| Event | Owner and firing condition |
| --- | --- |
| `$pageview` | Browser initial load and committed product navigation, deduplicated on initialization while actual navigations retain their counts; `$pathname`, `$current_url` and `$host` contain only safe production paths; the first of a page load adds `referrer` (also `$referring_domain`) and campaign labels. |
| `$identify`, `app_opened` | Product browser after the account and its setting are read, unless analytics are off; identify links the page's anonymous visit and app_opened fires once per product page lifetime/account. |
| `signed_up` | Auth account creation, before email verification: `method` and approved first-touch attribution. |
| `onboarding_finished` | Compatible server outcome after welcome is saved, with a fixed learning kind, `joined` for an account arriving with a deck, or `skipped`; no typed language answer is collected. |
| `signed_in` | Auth session creation; do not interpret as every explicit sign-in click or as a session refresh. |
| `review_graded` | Accepted server grade: unchanged `mode`, `grade`; replay of the same review ID adds no event. |
| `cards_added` | Committed additions, excluding duplicate cards and edits: `source`, `count`. `typed`, `api`, `ai_mcp`, `anki`, `mochi`, `lymi` are implemented; CSV/Quizlet remain reserved until adapters exist. `ai_mcp` denotes the channel, not authorship. |
| `card_added` | Legacy addition event retained for existing consumers; never sum with `cards_added`. |
| `welcome_step_viewed`, `welcome_step_finished` | Browser observes current guide step and progression for `deck`/`cards`; first accepted non-import grade finishes `review` on the server. The welcome flow uses `hello`, `kind`, `language`, `goal`, `start`; an account arriving with a deck uses only `hello` and `goal`; progression and saved completion fire step outcomes, and a saved Skip fires its current step with `skipped=true`. The server emits `setup` once for overall completion or Skip, with `skipped=true` only when both learning kind and daily goal are absent. Existing progress on mount is not replayed as completion, so a deck or cards added away from the guide finish no step; measure that progress with `cards_added`. |
| `empty_state_option_picked` | Explicit guide or empty-library action; fixed option, never displayed text. The welcome start choice counts once its answers are saved. Reserved options are emitted only when their UI exists. |
| `import_started` | Import successfully claimed for writing: selected expected `card_count`, source and adapter. |
| `import_finished`, `import_failed` | Terminal transition: actual newly added `card_count`, including partial failed work. Legacy `import_finished(outcome=failed)` accompanies `import_failed`; success has `outcome=done`. Retry does not duplicate terminal delivery. |
| `daily_goal_set` | Saved first choice or changed value: `value`, `is_change`; not an optimistic click or refetch. |
| `reminder_prompt_shown`, `reminder_prompt_accepted` | A browser permission request from default permission, then its granted result. Permission acceptance is not proof the subscription saved; failures remain separate. |
| `public_deck_viewed` | Cookieless browser view of a published slug, with active locale; separate from aggregate publisher request counts. |
| `add_to_lymi_clicked`, `deck_added` | Browser add intent, then server's new published membership. Existing membership is not another addition. |
| `first_session_started` | First accepted non-import grade on a published deck, once per account/deck; includes public `deck_slug`. Imported history does not activate the learner. |
| `review_session_finished`, `review_session_abandoned` | Browser review leg: `session_id`, first-session eligibility, net recall counts and fixed ending/reason. |
| `mcp_tool` | MCP tool result: fixed tool name, success/error and elapsed milliseconds, with no request or response content. |
| `enrichment_finished`, `deck_joined` | Existing server outcome contracts remain available. |

A measured review leg begins when a card is presented. Finished legs end at a goal or confirmed empty queue and count net recall attempts since presentation, including repeated cards and subtracting Undo. Abandonment reports net `cards_done` against the frozen initial planned `card_count`; left, navigation and pagehide are observable exits. Continue starts another leg and does not retain first-session eligibility after actual work. An empty screen, failed refresh or offline exhaustion cannot manufacture a completion. Browser shutdown delivery is best effort; absence of abandonment proves nothing. These counts are attempts, not unique cards, and are distinct from accepted server grades queued offline.

The first-review marker is stored separately from mutable/imported history, so retries and Undo do not repeat activation. It is written after the grade's response, only while PostHog is configured. Historical non-import reviews seed existing learners as already active. Marker errors never roll back grades. Account deletion cascades markers and settings with the account.

## Extend and verify

For each feature, state the measurement question in the PR's Instrumentation section, reuse or add a catalog event, document its owner and exact firing condition here, and test allowed properties plus meaningful retry/failure behavior. Use fixed categories and counts rather than user-entered strings. Keep outcome ownership on the server and interaction ownership in the browser. If no event answers a useful question, state why. Add properties compatibly; a changed meaning needs a new event or explicit schema migration.

Run contract/identity tests, service tests and the repository gates. Development and previews never send to PostHog. Before using a production funnel, verify one journey in live ingestion: cookieless public page with country → sign-up with its first touch → identify → committed membership/cards → accepted review, matching distinct IDs and locale; also verify that an account with `analytics_consent` set to `false` stops delivery. Do not infer live delivery from a passing test or a green deploy. Filter person `is_internal=true` out of growth charts. Project timezone is Europe/Tallinn. Source maps and native mobile instrumentation remain separate work; shared contracts can be reused by a React Native adapter without importing this DOM-based browser module.

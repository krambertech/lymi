# Imports and exports

Import starts from the Import group at the end of Settings, one plate with a row per app Lymi reads; `/import` redirects there. Each app has its own page, such as `/import/anki`, `/import/mochi` and `/import/noji`, with that app's file, export steps and guide, because the steps differ and a later source adds a row rather than another menu item. From then on every screen names the app the file came from. A Pleco export and a Quizlet set are both .txt files, so the page names its app when the upload starts and the file's content decides once it is read.

An import is one screen whose body follows the import's state: choose a file, the file on its way, the preview, the cards being written, and the end. The address holds the import, so leaving and coming back finds it where it was, and Activity lists every import and opens the same screen.

The preview asks one question per screen, in the order the answers depend on each other, and skips a question with nothing to ask: **Which decks do you want in Lymi?** when the file holds more than one, a language for each chosen deck Lymi could not place (which, after the learner's usual language, happens only before their first card), **Does this card look right?** for each kind of note, then what the import brings with the button that starts it. There is no step counter, because the number of questions changes with the file. Back sits beside the actions on a desktop and under them on a phone, never above the question.

The decks are a checklist in which the whole row ticks the box, each with its card count and how many arrive Known.

A language comes from the file when it records one, then the deck's name, then its cards: a script only one language uses settles it, and otherwise the text model reads a sample of terms from every unplaced deck in one call, so the question appears only when that fails.

Each kind of note gets its own card, drawn the way the card page draws a card, with **Change fields** and **Looks right** side by side; they share the row evenly and stack when a translation cannot fit. The kinds that together hold 95% of the notes are asked, and a tail of two or more rare kinds is one line on the last card with **Check those too**. The card is the one decision a learner cannot fix afterwards without archiving the import, so it is asked where the answer is visible.

The last screen is titled **Ready to import N cards**. Three figures in one plate with hairlines between (cards, known, past reviews; two for Noji and Pleco, whose files carry no reviews), then plain lines that each start with a mark: a green check for what is kept (cards that arrive Known, due dates, pictures, recordings, examples' recordings, cards an earlier import brought, and Pleco's categories by name as they become tags) and a muted minus for what is skipped or left out (terms already in Lymi, suspended cards, long text, recordings Lymi cannot play, examples' recordings Lymi cannot play, second clips, pitch accents drawn only as graphs, notes Lymi cannot ask). Under them, one plate repeats the answers (decks, languages, cards), each with Change; languages open a dialog rather than a step, because most imports never showed one. The primary is **Import N cards**, with a line under it that the whole import can be undone from Activity, and Cancel import under that.

While a file uploads the screen says to keep Lymi open; once it is reading or writing it says the app can be closed. A known amount of work is the `Progress` track; reading, whose length is not known, sweeps a third of the track and holds still under reduced motion. The end names the count, offers Open Library, and keeps Archive import, a danger button as Archive deck is, beside a sentence saying exactly what it hides, with Undo in the toast.

Export is a sheet the learner asks for from a deck's menu or from **Export library** in the Export group of Settings, just above Import. It offers the formats as radio rows, **Anki package** first because most files leave for another app, then **Lymi file**, and **Spreadsheet** for one deck. The primary is **Export**. The Export button spins while the file is written; only past a second and a half does the sheet trade the formats for the working bar and say it can close because the file waits in Activity for a day, so a small deck never flashes a screen it leaves at once; when it is ready, the sheet names the file, its cards and size, says until when it can be downloaded, and its primary becomes **Download**. Activity lists exports above imports, each row with its format, date and card count and a Download button while the file exists.

On the phone the same screens are pages pushed from Import in You, Library's plus, Welcome's start choice and Activity, at the web's paths ([ADR 0036](../adr/0036-setup-runs-on-the-phone.md)). Each app's page puts the export steps first and **Choose file** last, at the thumb, because on a phone the file is usually exported just before it is chosen; it opens iOS's Files picker, and the steps end by saving the file to Files. The preview's questions keep the web's order, each a screen with its answers full-width at its foot and Back under them; **Change fields** and the languages open in place of the question as a list of rows, each a Select, rather than a dialog. Quizlet's page takes the text from Paste or a .txt file. Export is a sheet from Export library in You, Export deck in a deck's ⋯ and an export in Activity: a tap on a format starts it, so the sheet has no Export button, and the finished file's primary is **Save or share**, which downloads it and, once the sheet has gone, opens iOS's share sheet. A spreadsheet is written on the phone from the deck's cards and goes straight to the share sheet.
